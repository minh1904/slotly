## Why

Better-Auth is wired up (`src/lib/auth.ts`, `email/password` provider enabled, route handler at
`src/app/api/auth/[...all]/route.ts`, client at `src/features/auth/client.tsx`) but there is no
page a user can actually log in from. The Figma design (`Slotly` file, node `5:7`) provides the
target layout — a two-panel screen (form panel + image panel) — which needs to be adapted for the
login use case and implemented against the existing Better-Auth email/password setup.

## What Changes

- Add a `/login` route rendering a two-panel layout (form on one side, image panel on the other),
  following the visual structure of the Figma reference.
- Add a client-side login form (email + password) under `features/auth/components/`, submitting
  directly via `authClient.signIn.email(...)` (Better-Auth's client SDK), matching the pattern
  Rallly uses for its own email/password sign-in — no server action in the submit path, since
  Better-Auth's client already handles the request/cookie exchange.
- Add inline field-level validation (react-hook-form + zod) and inline error display for failed
  sign-in attempts (invalid credentials, etc.).
- Add a loading state on submit (disabled button + spinner) to prevent double-submit.
- On successful login, redirect to the app's home route.
- Install the specific shadcn/ui primitives needed (`button`, `input`, `label`, `form`) via
  `bunx shadcn add` — this project has no shadcn components installed yet; CLAUDE.md's
  architecture section already establishes shadcn/ui as the default for MVP UI primitives, so this
  is not a new-dependency decision, only which components to pull in first.

Out of scope for this change (not part of the Figma reference or current Better-Auth config, can
be separate follow-ups): sign-up/registration page, forgot/reset password flow, OAuth/social
login, email OTP passwordless login.

## Capabilities

### New Capabilities
- `auth/login`: the login page and form — rendering the two-panel layout, collecting
  email/password, validating input, submitting to Better-Auth, handling success/error states.

### Modified Capabilities
(none — no existing specs in this repo yet)

## Impact

- New route: `src/app/login/page.tsx` (or `src/app/(auth)/login/page.tsx`, decided in design.md).
- New feature UI: `src/features/auth/components/login-form.tsx` (client component).
- New shared UI: `src/components/ui/{button,input,label,form}.tsx` (generated by shadcn CLI).
- New dependencies pulled in transitively by the shadcn `form` component: `react-hook-form`,
  `@hookform/resolvers`, `zod` (zod may already be a implicit peer via Better-Auth; confirmed at
  implementation time) — each is a shadcn/ui-standard dependency already implied by CLAUDE.md's
  "use shadcn/ui as-is" policy, called out here for visibility.
- No schema/migration changes — uses the existing Better-Auth `User`/`Account` tables as-is.
- No changes to `src/lib/auth.ts` — `emailAndPassword.enabled: true` is already sufficient.
